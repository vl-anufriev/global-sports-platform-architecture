# 7. Критические бизнес-сценарии

## CS-01. Запись тренировки

1. Пользователь запускает тренировку.
2. Приложение начинает собирать доступные данные.
3. Данные сохраняются во время тренировки.
4. Пользователь завершает тренировку.
5. Результаты передаются в backend.
6. Training валидирует данные и сохраняет тренировку вместе с Outbox Event в одной транзакции.
7. Backend подтверждает сохранение пользователю; тренировка доступна в истории.
8. Outbox Publisher публикует `TrainingCompleted`, и фоновые consumers обновляют показатели и прогресс.

### Почему критический

Это основной пользовательский сценарий, от которого зависит большинство остальных возможностей системы.

## CS-02. Работа без стабильного интернета

1. Пользователь начинает тренировку при наличии сети.
2. Связь пропадает.
3. Мобильное приложение продолжает фиксировать тренировку локально.
4. Пользователь завершает тренировку.
5. После восстановления связи данные синхронизируются.

## CS-03. Массовое соревнование

1. Создаётся глобальный или региональный челлендж.
2. Большое число пользователей присоединяется.
3. Пользователи выполняют тренировки.
4. В систему одновременно поступает большое количество результатов.
5. Результаты обрабатываются.
6. Обновляется рейтинг.

## CS-04. Поиск партнёров для тренировки

1. Пользователь выбирает тип спорта.
2. Указывает область поиска.
3. Система находит подходящих пользователей.
4. При наличии разрешения могут учитываться текущая активность и маршрут.
5. Пользователь присоединяется к группе или связывается с другим пользователем.

## CS-05. Интеграция внешнего устройства

1. Пользователь подключает устройство.
2. Система получает разрешение.
3. Данные устройства преобразуются во внутреннюю модель.
4. Показатели связываются с тренировкой пользователя.
