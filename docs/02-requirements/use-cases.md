# 12. Описание сценариев использования

Сценарии использования описывают основные способы взаимодействия пользователя
и внешних систем с приложением.

---

## UC-01. Регистрация тренировки

### Актор

Пользователь.

### Предусловия

- Пользователь авторизован.
- Пользователь имеет доступ к мобильному приложению.

### Основной сценарий

До завершения тренировки пользователь выбирает её тип и нажимает «Начать тренировку».
Мобильное приложение собирает доступные данные, включая дополнительные показатели
подключённого устройства при его наличии.

1. Пользователь завершает тренировку.
2. Mobile отправляет данные тренировки backend-системе.
3. Training валидирует данные.
4. Training сохраняет тренировку и Outbox Event `TrainingCompleted` в одной локальной транзакции.
5. Backend подтверждает успешное сохранение пользователю.
6. После этого Outbox Publisher публикует `TrainingCompleted` в Event Bus.
7. Фоновые consumers независимо выполняют обработку события.
8. Analytics обновляет статистику.
9. Gamification проверяет достижения.
10. Recommendations обновляет рекомендации при необходимости.

Пользователь не должен ждать выполнения Analytics, Gamification или Notifications,
чтобы получить подтверждение сохранения тренировки. Пункты 8–10 выполняются
независимо и не задают последовательность между consumers.

Если Gamification обнаружил новое достижение, он сохраняет его и публикует
`AchievementEarned`. Notifications подписывается на `AchievementEarned` и отправляет
уведомление с учётом настроек приватности.

Результаты вторичной обработки могут появляться с небольшой задержкой
из-за eventual consistency.

Надёжная публикация события описана в [ADR-014](../adr/ADR-014-transactional-outbox.md).

### Альтернативный сценарий

Если во время тренировки отсутствует соединение с интернетом:

1. данные сохраняются локально на мобильном устройстве;
2. тренировка продолжается без соединения с backend;
3. пользователь завершает тренировку;
4. данные остаются на устройстве;
5. после восстановления соединения приложение выполняет синхронизацию.

## UC-02. Просмотр и сравнение прогресса

### Актор

Пользователь.

### Основной сценарий

1. Пользователь открывает раздел статистики.
2. Система получает историю тренировок пользователя.
3. Analytics получает или рассчитывает агрегированные показатели.
4. Пользователю отображается изменение спортивных результатов во времени.
5. Пользователь может сравнить свои показатели:
    - со своими предыдущими тренировками;
    - с пользователями своего региона;
    - с доступными результатами профессиональных спортсменов.

---

## UC-03. Поиск людей для совместной тренировки

### Актор

Пользователь.

### Предусловия

- Пользователь авторизован.
- Пользователь разрешил использование необходимых данных местоположения.

### Основной сценарий

1. Пользователь выбирает интересующий вид спорта.
2. Пользователь задаёт область или параметры поиска.
3. Social-компонент получает параметры поиска.
4. Система ищет подходящих пользователей или группы.
5. При поиске учитываются настройки приватности найденных пользователей.
6. Пользователю возвращается список доступных участников или групп.
7. Пользователь может вступить в группу или инициировать взаимодействие.

---

## UC-04. Участие в спортивном соревновании

### Актор

Пользователь.

### Основной сценарий

1. Пользователь выбирает соревнование или спортивный челлендж.
2. Система регистрирует пользователя в качестве участника.
3. Пользователь выполняет тренировку.
4. Training сохраняет результат и Outbox Event в одной транзакции и подтверждает сохранение пользователю.
5. Outbox Publisher публикует событие `TrainingCompleted`.
6. Gamification проверяет правила соревнования.
7. Результат пользователя учитывается в соревновании.
8. Рейтинг обновляется.
9. Пользователю отображается актуальный результат.

### Особенности

Во время массовых соревнований количество одновременно поступающих результатов
может быть значительно выше обычной нагрузки.

Обновление общего рейтинга допускается выполнять асинхронно.

---

## UC-05. Подключение фитнес-устройства

### Актор

Пользователь.

### Основной сценарий

1. Пользователь выбирает поддерживаемое устройство или источник данных.
2. Приложение запускает процесс подключения.
3. Пользователь предоставляет необходимые разрешения.
4. Integration Layer получает данные внешнего поставщика.
5. Внешняя модель данных преобразуется во внутреннюю модель платформы.
6. Полученные показатели передаются в Training.
7. Training связывает показатели с соответствующей тренировкой.

---

## UC-06. Получение персонального предложения

### Актор

Пользователь.

### Основной сценарий

1. Пользователь выполняет тренировки.
2. Система формирует агрегированную информацию о спортивной активности.
3. Recommendations определяет потенциально релевантный контент.
4. Promotions выбирает доступные предложения с учётом контекста и региона.
5. Пользователю отображается предложение.
6. При необходимости пользователь переходит в существующее приложение компании для покупки товара.

---

## UC-07. Создание спортивной группы

### Актор

Пользователь.

### Основной сценарий

1. Пользователь создаёт новую спортивную группу.
2. Указывает вид спорта и параметры группы.
3. Social сохраняет группу.
4. Пользователь приглашает других участников либо делает группу доступной для поиска.
5. Другие пользователи могут находить группу и присоединяться к ней.

---

## UC-08. Получение достижения

### Актор

Пользователь.

### Основной сценарий

1. Пользователь завершает тренировку.
2. Training сохраняет тренировку и Outbox Event в одной транзакции, подтверждает сохранение; Outbox Publisher публикует `TrainingCompleted`.
3. Gamification получает событие.
4. Проверяются условия получения достижений.
5. При выполнении условия Gamification сохраняет достижение и публикует `AchievementEarned` в Event Bus.
6. Notifications получает `AchievementEarned` и отправляет пользователю уведомление.
7. При разрешении пользователя информация может быть доступна друзьям.
