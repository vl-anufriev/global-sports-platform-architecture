# ADR-009. Географический поиск пользователей

**Статус:** Proposed

## Context

Пользователь должен иметь возможность находить:

- людей поблизости;
- пользователей с похожими маршрутами;
- людей, тренирующихся в определённой области;
- при соответствующих настройках — пользователей, тренирующихся сейчас.

Обычного поиска по атрибутам профиля может быть недостаточно для эффективного
географического поиска при большом количестве пользователей.

## Decision

Предусмотреть специализированный механизм географического поиска.

Social-компонент остаётся владельцем бизнес-правил поиска.

Для выполнения географических запросов допускается специализированный
геопространственный индекс или хранилище.

Конкретная технология на данном этапе не выбирается.

## Alternatives

### Выполнять географические запросы непосредственно к основной БД

Может быть достаточно на раннем этапе.

Не гарантируется достаточная производительность при большом масштабе.

### Использовать отдельный поисковый движок сразу

Не принимается как обязательное решение до появления количественных требований.

## Consequences

### Positive

- возможность масштабировать географический поиск независимо;
- эффективный поиск по расстоянию и области.

### Negative

- появляется дополнительная проекция данных;
- необходима синхронизация;
- повышаются требования к защите геолокации.
