# ADR-004. API Gateway как единая точка входа

**Статус:** Accepted

## Context

Backend состоит из нескольких доменных компонентов.

Мобильное приложение не должно:

- знать расположение каждого компонента;
- самостоятельно выбирать backend-сервис;
- реализовывать отдельную инфраструктурную интеграцию с каждым сервисом.

Также необходимо централизованно реализовать ряд cross-cutting функций.

## Decision

Использовать API Gateway как внешнюю точку входа в backend.

API Gateway отвечает за:

- маршрутизацию запросов;
- базовую проверку аутентификации;
- rate limiting;
- централизованное применение инфраструктурных политик;
- сокрытие внутренней структуры системы от клиента.

Бизнес-логика в API Gateway не размещается.

## Alternatives

### Прямой доступ к сервисам

Отклонено из-за:

- сильной связанности клиента с backend;
- усложнения security;
- сложности изменения внутренней топологии.

### Backend For Frontend

Может быть рассмотрен дополнительно при появлении нескольких существенно
различающихся типов клиентов.

На текущем этапе отдельный BFF не требуется.

## Consequences

### Positive

- единая внешняя точка входа;
- упрощение мобильного клиента;
- централизованный rate limiting;
- внутренняя архитектура скрыта от клиента.

### Negative

- Gateway становится критически важным компонентом;
- требуется горизонтальное масштабирование;
- необходимо избегать переноса бизнес-логики в Gateway.
