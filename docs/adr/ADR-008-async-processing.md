# ADR-008. Асинхронная обработка вторичных операций

**Статус:** Accepted

## Context

Основная ценность сценария завершения тренировки — надёжно сохранить результат.

Расчёт аналитики, достижений, рекомендаций и отправка уведомлений не должны
увеличивать вероятность отказа основной операции.

## Decision

Разделить обработку на:

### Critical path

Выполняется синхронно:

1. принять тренировку;
2. проверить данные;
3. сохранить тренировку и Outbox Event в одной локальной транзакции;
4. подтвердить сохранение пользователю.

### Background processing

Выполняется асинхронно:

- аналитика;
- достижения;
- рейтинги;
- рекомендации;
- уведомления.

```text
Mobile
   |
   v
Training
   |
   +--> Persist Training + Outbox Event
   |
   +--> Success response
   |
   +--> Outbox Publisher
           |
           v
       Event Broker: TrainingCompleted
           |
           +--> Analytics
           +--> Gamification --> AchievementEarned --> Event Broker --> Notifications
           +--> Recommendations
```

Outbox Publisher доставляет сохранённое событие независимо от пользовательского
ответа, согласно [ADR-014](ADR-014-transactional-outbox.md). Уведомление о достижении
отправляется только по `AchievementEarned` после проверки и сохранения достижения
в Gamification. Повторные сообщения обрабатываются идемпотентно.

## Alternatives

### Выполнять всё синхронно

Отклонено из-за увеличения latency и зависимости основной операции от
вторичных компонентов.

## Consequences

### Positive

- быстрое завершение основного сценария;
- изоляция отказов;
- независимое масштабирование workers.

### Negative

- пользователь может увидеть некоторые результаты с задержкой;
- требуется отображать состояние обработки;
- необходим мониторинг фоновых задач.
