# ADR-007. Выделение интеграционного слоя

**Статус:** Accepted

## Context

Приложение должно поддерживать различные внешние источники данных:

- спортивные часы;
- датчики;
- мобильные fitness API;
- существующие приложения компании.

Каждый поставщик имеет собственные:

- API;
- форматы данных;
- модели авторизации;
- ограничения.

Прямая интеграция домена Training со всеми поставщиками создаёт сильную
связанность.

## Decision

Выделить Integration Layer.

Integration Layer отвечает за:

- взаимодействие с внешними API;
- преобразование внешних форматов;
- нормализацию данных;
- обработку особенностей поставщика;
- защиту основных доменов от изменений внешних API.

Для внутренних компонентов используется единая внутренняя модель данных.

## Alternatives

### Интеграция непосредственно внутри Training

Отклонена из-за сильной зависимости бизнес-логики от внешних систем.

### Единый универсальный внешний стандарт

Нельзя гарантировать поддержку одного стандарта всеми производителями.

## Consequences

### Positive

- проще подключать новые устройства;
- изменение API поставщика локализовано;
- доменная модель не зависит от внешнего формата.

### Negative

- появляется дополнительный компонент;
- необходимо поддерживать адаптеры;
- требуется тестирование интеграций.
