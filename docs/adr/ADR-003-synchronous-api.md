# ADR-003. Синхронное API для пользовательских операций

**Статус:** Accepted

## Context

Часть операций приложения требует немедленного ответа.

Например:

- получение профиля;
- просмотр тренировки;
- получение расписания;
- поиск группы;
- получение настроек пользователя.

Использование событий для таких запросов усложнило бы клиентскую логику и
увеличило время получения результата.

## Decision

Для операций request-response использовать синхронные API.

Синхронное взаимодействие применяется в случаях, когда вызывающая сторона
ожидает непосредственный результат операции.

Event-driven взаимодействие используется для фоновых процессов.

## Alternatives

### Все взаимодействия через события

Отклонено, поскольку пользовательские request-response сценарии становятся
излишне сложными.

### Прямой доступ клиента к нескольким сервисам

Отклонено из-за усложнения мобильного клиента и увеличения связанности клиента
с внутренней архитектурой backend.

## Consequences

### Positive

- простая модель взаимодействия для клиента;
- предсказуемый request-response;
- проще обработка пользовательских ошибок.

### Negative

- синхронные зависимости могут распространять отказ;
- требуется управление timeout;
- необходимы retry и circuit breaker для некоторых взаимодействий.
