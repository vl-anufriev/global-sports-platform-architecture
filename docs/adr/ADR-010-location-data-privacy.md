# ADR-010. Защита геолокационных данных

**Статус:** Accepted

## Context

Система может обрабатывать:

- маршруты тренировок;
- текущее местоположение;
- регулярные места тренировок;
- время тренировок.

Раскрытие такой информации может создать существенные риски для приватности
пользователя.

## Decision

Использовать Privacy by Design для геолокационных функций.

По умолчанию точные географические данные пользователя не должны быть публичными.

Пользователь должен явно контролировать:

- кто видит тренировку;
- кто видит маршрут;
- разрешён ли поиск пользователя поблизости;
- разрешено ли отображение текущей активности.

Система должна передавать другим пользователям минимально необходимую точность
геолокации.

Например, для поиска спортсменов поблизости не обязательно раскрывать точные
координаты человека.

## Alternatives

### Публичные данные по умолчанию

Отклонено из-за риска раскрытия чувствительной информации.

### Полностью запретить географические функции

Отклонено, поскольку географический поиск является одним из бизнес-требований.

## Consequences

### Positive

- снижение privacy-рисков;
- пользователь контролирует свои данные;
- повышается доверие к платформе.

### Negative

- усложняется модель авторизации;
- требуется consent management;
- необходимо учитывать privacy settings при поиске и кешировании.
