# ADR-011. Возможность регионального развёртывания

**Статус:** Proposed

## Context

Платформа предназначена для пользователей по всему миру.

Размещение всей системы в одном регионе потенциально приводит к:

- высоким сетевым задержкам;
- ограничению масштабирования;
- повышенному влиянию регионального отказа;
- возможным ограничениям по месту хранения данных.

При этом точные требования по latency, availability и data residency пока
не определены.

## Decision

Архитектура должна допускать развёртывание приложения в нескольких регионах.

На данном этапе не фиксируется конкретная модель:

- active-active;
- active-passive;
- home region;
- региональное разделение пользователей.

Окончательное решение принимается после появления количественных требований.

## Alternatives

### Один глобальный регион

Проще и дешевле.

Может использоваться на раннем этапе или MVP.

### Active-active с первого релиза

Обеспечивает высокую доступность, но значительно усложняет:

- данные;
- маршрутизацию;
- эксплуатацию;
- стоимость.

Поэтому не выбирается автоматически.

## Consequences

### Positive

- архитектура не блокирует глобальное развитие;
- можно снижать latency;
- повышается потенциальная отказоустойчивость.

### Negative

- multi-region значительно усложняет работу с данными;
- увеличивается стоимость;
- требуется стратегия consistency.
